# DSH Delegation Router

主 Agent 已决定委派后，从用户维护的固定候选模型池中选择模型，通过 DSH 原生 subagent 创建文本子会话。插件不决定是否委派、不切换主模型、不编排 Agent Teams，也不增加分类模型调用或评分系统。

## 配置

每个候选都是一个完整执行档案：名称、固定 `provider / model / effort` 和适用说明。同一模型可以配置多个真实思考等级，主 Agent 选择整个档案，运行时不临时改档。

### 当前预设

在设置页顶部用「当前预设」下拉框切换；展开默认折叠的「预设操作」可新建、复制、重命名或删除。每个 DSH Profile 最多保存 32 套自由命名的预设，不预设场景或自动分类。

- **新建／复制**：新建沿用当前默认项、清空新预设的分工说明，保存后切换；复制保留分工与默认项，修改副本不影响原预设。两者都不另建模型池。
- **重命名／切换**：预设名称去除首尾空白后须为 1–120 字符、无控制符、不区分大小写判重。切换单次提交并验证保存回执，不取消已有委派，也不重置历史审计或配额计数；仍受 `CONFIG_BUSY` 限制。
- **删除**：仅能删除非当前预设，须二次确认；不改全局候选，也不自动回退。不能删除当前或最后一套。

未保存修改、输入不完整、生成／校验中、连接重置或保存结果不确定时，不能管理或切换预设。旧草稿和旧界面回调（含 A→B→A 及 IME）不能改写另一预设。

### 预设详情

从已配置的候选中选择**默认委派模型**，下拉列表显示 Provider、模型和思考档位，不必刷新目录。按需展开「手动编辑」，修改当前预设中的档案名称和分工说明。每套预设只保存这些文字覆盖和默认项，不修改模型池；新默认项只影响当前预设中后续未指定档案的委派。

完整有效的手动修改在停止输入约 600ms 后自动保存；冲突或写入结果不确定时停止自动重试。未保存的修改不妨碍填写生成模型、范围和要求，但须保存或明确放弃后才能生成。

### 可选模型

同一 DSH Profile 的所有命名预设共用一个全局模型池。在「可选模型」增删档案，或修改其固定的 `Provider / model / effort`，变更对所有预设生效。路由启用开关和配额也是全局设置，高级配额按需展开；审计路径保持全局，设置页不编辑原值。

仍被任一预设设为默认项的档案不能删除，须先去相应预设更换默认项。删除其他档案会同步清除该档案在各预设中的文字覆盖，不自动更换默认项。

### 生成草稿

1. 从 DSH 原生模型目录选择**生成模型及其真实思考等级**。它负责生成草稿，不必是可委派档案。
2. 在**允许委派的档案**中，从已配置的全局池勾选本次允许的档案。该范围是草稿的硬边界；若所需模型或档位不在池中，先到「可选模型」配置，再重新生成。
3. 输入使用要求，例如「机械任务优先低投入，复杂排障用高投入；不知道能力或价格时明确说明」。点击「生成草稿」才发起一次推理（可能产生费用），只发送范围和要求，不发送当前会话正文、审计日志或凭据；模型只能引用所选档案 ID，不能编造 Provider、模型或档位。
4. 审阅草稿、警告和与当前预设的对照，可调整名称、分工和默认项。生成和编辑都不会自动保存或启用路由。确认后显式点击「校验并应用」；服务端重新核对模型元数据和范围，通过后验证保存回执。命名预设模式下，应用只更新当前预设的名称／分工覆盖和默认项，**不修改全局模型池**或其他预设。

**旧版 v3 单套**：仍从原生模型目录搜索模型、直接勾选允许的真实档位（仅明确无可配档位时用 `null`），生成替换候选。审阅时也可从草稿移除档案；校验通过后替换候选和默认项（可初始化空池），保留启用状态、配额和审计路径。

模型目录显示加载状态、模型数和刷新时间。点击「刷新模型」只重读目录，不触发推理或改变配置。各 Provider 独立限时 5 秒，异常不阻塞其他 Provider；连接或整体读取超过 20 秒可重试，迟到结果不会覆盖新目录。

范围与要求冲突、目录不可用、非法返回、超时、连接重置或配置变化时，不自动换模型、重试或覆盖。修改输入、范围或目录后须重新生成。向导输入和未应用草稿只保留在当前页面内存，不按预设另存。应用后仍可手动调整，实际委派仍受宿主授权限制。

### 配置兼容性

v3 单套配置继续读取及编辑，普通保存不迁移。首次新增、复制或重命名时保存为 v4，原候选成为全局池，原名称、分工和默认项完整保留。示例（关闭状态可省默认项）：

```json
{
  "ui": {
    "schemaVersion": 4,
    "enabled": false,
    "candidates": [],
    "activeConfigId": "config-1",
    "configs": [{ "id": "config-1", "name": "我自己定义的预设", "overrides": [] }]
  }
}
```

预设覆盖为 `overrides: [{id, name, description?}]`，只能引用全局候选 ID；省略说明则继承全局说明，空串则清空。启用时每套预设都须有有效默认项。缺失／无效的当前预设、悬空引用或把模型路由／配额放入某套预设都会被拒绝，不自动回退。旧版插件不支持 v4；降级前须备份并将全局池与选中覆盖合成为 v3 单套策略。

### 思考等级建议

- 档位以所选 provider/model 的真实目录为准，不跨模型比较同名档位；不虚构 `medium` 或 `default`。目录查询失败不等于无档位。
- 任务边界清晰、机械转换且容易验证时考虑较低投入；常规实现考虑均衡投入；多约束、高不确定性、难验证问题考虑较高投入。只有目录/用户提供了可靠语义，才能作这种映射，不能把列表顺序当作档位排名。
- 不默认最高档，不因文件多、输入长或回答要详细就自动升档；高等级不能替代资料、测试、权限或独立复核。
- 默认生成少量职责清晰的档案（通常 3–5 个，范围很小时可以更少），不是每个模型每个档位都要生成。模型能力、价格或速度没有可靠依据时明确说明未知。
- 适用说明建议包含「适用、不适用、选择依据」。这是主 Agent 的选择参考，不是强制任务分类引擎；程序强制保证的是结构、范围和真实等级，不能证明自然语言要求已全部满足。

配置入口只有 `ui` 和可选的绝对路径 `auditFile`。`ui.schemaVersion` 支持 3（原有单套）和 4（命名配置集），每套运行策略仍为严格 v3。未提供配置时默认关闭且候选池为空。启用时必须显式指定当前套清单内的 `defaultCandidateId`。

- `candidates`：每项包含 `id / name / provider / model / effort`，可选 `description`。
- `effort`：宿主模型目录公布的真实值；明确无可配置档位时填 `null`。目录不可用不等于没有档位。
- `limits`：可设置 `maxPendingStarts`、`maxActivePerModel`、`maxCreationsPerParent`、`metadataTimeoutMs`。

参见默认关闭的[候选配置示例](<examples/candidates.json>)。模型目录可见不代表获得创建授权；适用说明不授予权限或证明模型能力。

## 工具

| 工具 | 职责 |
| --- | --- |
| `delegation_routes` | 列出授权范围内的候选、默认项及配置代际，不进行模型预检 |
| `routed_subagent` | 按 `candidate_id` 创建子会话；省略时使用默认项，携带 `policy_revision` 防止过期选择 |
| `router_status` | 只读当前父作用域的配置状态、创建回执及真实请求证据 |
| `router_reconcile` | 用宿主持久证据结清已接受的子会话，不创建或恢复 Agent |

明确的用户选择优先；否则主 Agent 按任务和适用说明选择，没有明确理由时使用默认项。插件只校验被选中的候选，不自动换模型、降档或绕过宿主 guard/审批。

## 安全边界

- 创建前、异步预检后和原生派发前均检查身份、授权、配置代际与取消状态；原生准备阶段不能改写选中的模型、档位或绑定的子名称。
- 同一宿主 callId 幂等，相同 provider/model 共享并发配额；配置修改不会抹掉未结工作。
- `unknown` 和仅有 intent 的创建不能自动重试。结清需精确父子归属及宿主终态证据；不得通过换审计路径或删除锁绕过未结状态。
- selected 是意图，accepted 是创建回执，observed 是实际请求，settled 只是生命周期结束，不代表任务成功。
- 审计仅记录决策身份、候选、路由、状态和结清证据，不记录任务正文、适用说明或凭据。

## 安装与开发

运行环境：Node.js ≥22.15，DSH 准入范围见[包清单](<package.json#L23-L26>)。插件使用宿主已有模型目录与账号，由所选提供方决定模型调用费用。

```sh
npm test
npm run check
npm pack --ignore-scripts
node scripts/verify-pack.js ./dsh-delegation-router-0.12.0.tgz
```

以下命令从 GitHub Release 安装或更新到 `v0.12.0`。此地址固定到该版本，不会自动跟随以后的发布。

```sh
dsh plugin --profile desktop add https://github.com/CainDez/dsh-delegation-router/releases/download/v0.12.0/dsh-delegation-router-0.12.0.tgz
```

安装前检查未结委派并备份配置。

### DSH 兼容策略

- **准入范围以源码包清单为准**：`engines.dsh` 当前允许 `0.2.2-rc.3`，以及从 `0.2.2-rc.5` 起、低于 `0.2.2` 正式版的预发布；不包含 `rc.4`。范围内未来版本可以尝试加载，不代表已经逐版验证。安装包直接从相同源码打包，打包检查核对整个清单；不在打包时注入或改写版本范围。
- **加载后按能力检查**：缺少核心模块或关键委派能力时，不启用路由；设置 RPC 不可用不会阻止路由，模型目录和 AI 草稿按各自依赖启用。每次派发仍走原生守卫并检查回执契约，不自动回退到其他模型，也不改写配置。
- **CI 仅验证，不授予兼容性**：默认对官方 npm 运行时 `rc.3` 和 `rc.5` 跑隔离契约；可手动传入一个新候选版本验证，包括尚未纳入范围的版本。通过测试不会自动加入范围、修改清单或发布；需要调整范围时，先在源码中审查并提交变更，再从该提交打包。

本地也可运行以下命令（第二个参数可省略；提供时要求与宿主实际版本一致）。桌面 ASAR 请用对应 Electron 可执行文件加 `ELECTRON_RUN_AS_NODE=1` 替代 `node`。检查不连接运行中的 Profile、不创建 Agent、不发起推理。

```sh
node scripts/verify-host-matrix.js /path/to/dsh/package.json 0.2.2-rc.5
```
